Add/Edit Risk — Risk Detail Screen (ALIS)

Overview
The screen used to enter the actual risk/location/classification data behind an option, reached from the Risk/Option Detail page (itself reached by clicking an option's "$0.00 →" amount on the Quote tab — see `market-selection.md`, "Result: the option row"). As of this pass (2026-09-16), "Add/Edit Risk" no longer opens the legacy ASP.NET WebForms popup described in earlier versions of this document — it opens a new browser tab running a separate, modern Angular application at `ALIS.RD/APP/#/rdhome/...` (its tab title is still "ALIS", not the old ".::RISK DETAIL::." title). This is a platform upgrade, not a one-off quirk: the whole risk-entry experience has been redesigned into a step/breadcrumb-driven UI. Anything in a prior version of this document describing an ASP.NET popup, "Location"/"General Liability" as popup tabs sharing one page, or the "Property Information" + "Optional Coverage/Limits/Deductibles" two-tab building editor is superseded by this document.

This document covers: the Risk/Option Detail page's Risk tab, the new Add/Edit Risk screen's overall layout (top bar + General Liability / Commercial Property coverage tabs + Add Coverage), the General Liability breadcrumb (Limit & Deductible, Location, Classification, Additional Insured, Add-On Coverage, Additional Questions), the Commercial Property breadcrumb at the coverage level (Building, Location) and its own per-building wizard (documented in full in `commercial-property-building.md`), and the top-bar actions (Limit/Deductible Summary, Additional Data, Copy Risk Detail From, Location Renumber, Import/Export, Others, Add Coverage, Close & Apply).

The Risk/Option Detail page's Risk tab
Before any risk data exists, this tab is just an empty panel with the "Add/Edit Risk" button top right (see `market-selection.md` for the rest of this page's layout — header, Premium/Terms & Forms/Additional Interest/Other Details tabs, bottom bar). This part of the flow is unchanged from before. Clicking "Add/Edit Risk" opens the new ALIS.RD tab described below rather than a popup window.

The Add/Edit Risk screen — overall layout
A new browser tab, page title still just "ALIS". Top bar (dark red), left to right: the Insured name and submission number (e.g. "Jordan2 Brad - #SUB1655785-01"), then action buttons "Limit/Deductible Summary", "Additional Data", "Copy Risk Detail From", "Location Renumber", an "Import/Export" dropdown, an "Others" dropdown, and "Close & Apply" pinned at the far right. Below that: one tab per coverage on this risk — in this pass, "General Liability" and "Commercial Property" (both were present automatically for a "Commercial Package" coverage/COB, without deliberately adding either — Commercial Package still appears to bundle both by default, matching the old popup's behavior) — plus a green "+ Add Coverage" link.

Below the coverage tabs is a breadcrumb-style step nav specific to whichever coverage tab is selected (see the two breadcrumbs below). Navigating between breadcrumb steps has a real network round-trip behind it: the newly-selected step highlights immediately, but the page content can take 2–3 seconds to actually swap over — a screenshot taken right after clicking a step can still show the previous step's fields with only the breadcrumb highlight changed. Wait a beat (or check for the content heading to change) before assuming a click didn't register.

Add Coverage
The "+ Add Coverage" link next to the coverage tabs opens an "Add Additional Coverage" modal with a single "Select Coverage" dropdown and Close/Add buttons. With General Liability and Commercial Property both already present on this risk, the dropdown had nothing else to offer in this pass (not confirmed whether that's because Commercial Package genuinely only ever bundles those two, or because the dropdown excludes coverages already on the risk) — not fully exercised.

Top-bar actions — behavior / callouts
- Limit/Deductible Summary — opens a "Limits/Deductibles Summary" modal; empty in this pass (no premium/limit data had been entered yet on either coverage). Presumably a consolidated read-only rollup once data exists — the spiritual successor to the old popup's per-coverage "Risk Summary" concept, now centralized here instead of buried in a GL sub-tab.
- Additional Data — opens an "Additional Data" modal: a single-row form (No., Coverage dropdown, Level dropdown, Group Name dropdown defaulted to "Policy Issue", Parameter Name, Data Value 1/2/3) above a grid — functionally the same as the old top-level "Additional Data" tab, just relocated into a modal off the top bar. Empty/unfilled in this pass.
- Copy Risk Detail From — opens a "Risk Details Copy From" modal with a radio choice ("Current Submission" / "Another Submission") and a results area — showed "No Record Found" in this pass, same as the old popup. Note: pressing Escape while this modal is open does NOT close it (a deliberate improvement over the old popup, where Escape closed the whole thing) — use the modal's own × icon.
- Location Renumber — opens a "Location Information" modal: a "Location No." box, a "Renumber" link, a "Download" button, and a grid of every location on the risk with an editable Location No. per row, ending in Close/Update. Functionally the same as the old popup's version.
- Import/Export — a dropdown with a single option in this pass, "Risk Auto-Fill" (upload icon) — new, not present in the old popup at all. Not exercised (would presumably let you upload a file to bulk-populate risk data); its exact format/behavior is unconfirmed.
- Others — opens a "Property Options" modal with a "Minimum Premium" section (Level dropdown defaulted to "Policy", Coverage dropdown, Premium box) — the old popup's standalone "Minimum Premium" link, now relocated under this menu. "No data available" shown below it in this pass; unclear whether other option types live under this same menu (only one section was seen).
- Close & Apply — closes the whole screen and returns to the Risk/Option Detail Angular page, same as before. Important new behavior: Close & Apply now validates before closing. Attempting it in this pass (after adding a Commercial Property location + building, but before adding any General Liability Classification) produced a "Confirmation List" modal reading "- Classification details are required for each location in General Liability." and refused to close. This is a genuine behavior change from the old popup, which had no such validation — plan for Close & Apply to enumerate missing required data per coverage rather than silently succeeding.

General Liability breadcrumb
Six steps, in order: Limit & Deductible → Location → Classification → Additional Insured → Add-On Coverage → Additional Questions. Content and field-level behavior at each step matches the old popup's GL tab closely — this is a re-skin, not a re-design of the underlying data model — but every field that used to live on one long scrolling page is now its own step:
- Limit & Deductible — same fields as the old "Limits/Deductibles Of Insurance" section: General Aggregate + "Default Limit" dropdown, Products & Completed Operation Aggregate (Incl/Excl), Personal & Advertising Injury (Incl/Excl), Each Occurrence, Damage To Rented Premises (Excl), Medical Expense (Excl), Professional Limit (Incl/Excl — Excl pre-checked by default in this pass, matching the old popup), Deductibles column (Bodily Injury/Property Damage/Bodily Injury-Property Damage/Personal and Advertising Injury/Professional $ boxes, a Deductible Basis dropdown, an "Include LAE" checkbox), and on the right Per Project Aggregate/Per Location Aggregate checkboxes (None pre-checked), Job Cost($)/Job #/Premium($), and a Description of Work textarea (500-char counter shown).
- Location — an "Add New Location" form: "Copy Physical Address" checkbox, "Copy location(s) from" dropdown + Copy button, Address 1/Address 2 (required), City/State/Zip (required, split into City/State/Zip sub-boxes plus a combined display field with an × to clear), Territory, County, Latitude, Longitude, Description, and Cancel/Save Changes. Checking "Copy Physical Address" auto-fills Address 1/2, City/State/Zip, and Territory from the Insured's address after a short delay (~2s) — confirmed via the same test data as before (139 Southeast Main Street / Bethel, CT, 06801 / Territory 507) — but County was NOT auto-filled this time (it was "Fairfield" in the old popup's pass; blank here). After saving, the form collapses into a grid (Location No./Address/Description/City-State-Zip/Territory/County/Latitude/Longitude/View/Add/Edit/Copy/Delete) with an "Add Location" button top-right to add further locations. Note: General Liability has its OWN Location step, independent of Commercial Property's — adding a location on one coverage's Location step does not create it on the other; each coverage keeps its own location list (matching the old popup's finding that GL's Location grid didn't inherit Commercial Property's location).
- Classification — an "Add Classifications" form: Location dropdown (required — populated from locations already saved on GL's own Location step), Classification (type-ahead, with an × clear icon), Classification Code, "Enter Manually?" / TRIA checkboxes, Classification Description, Rate per dropdown, Final Rate, Exposure (with Incl/If Any checkboxes), Exposure Base dropdown, Minimum Premium($), Premium($) with a calculator icon and a "Round Amount" checkbox (checked by default), and a collapsible "Advance Premium" section. A running "Total Premium" total shows at the bottom of the step. This is a genuinely required step per the new Close & Apply validation (see above) — a location with no classification blocks closing the risk.
- Additional Insured — simpler than the old popup's version: "Enter ClassCode Manually?" checkbox, Form (type-ahead), Code, Description, Additional Insured Premium($), and Waiver of subrogation / Blanket Insured / Blanket Waiver of subrogation checkboxes. The old popup's separate "No. of Additional Insured" counter and ClassName/ClassCode Desc split fields aren't present in this layout — Form/Code appear to be the direct equivalent.
- Add-On Coverage — heading reads "Optional Coverage" (the breadcrumb label and the on-screen heading differ). A "Policy Level" checkbox, then a row: Coverage Type dropdown (required), Location dropdown, Class Code dropdown, Limit($) with N/A/Incl/Excl checkboxes; a second row: Aggregate($), Occurrence($), Opt Class Code, Opt Classification Desc; a third row: Exposure($) with Incl, Rate Per dropdown, Rate(%) with Incl, Premium with Incl + calculator + Round Amount (checked by default). This is the direct successor to the old popup's Location/Classification sub-tab's "Optional Coverage/Limits Details" grid, now promoted to its own breadcrumb step and shared with a Coverage Type dropdown instead of being commercial-property-only.
- Additional Questions — identical field set to the old popup's GL "Additional Question" sections, just combined onto one step instead of two stacked sections: a "Service Station Program" heading with Discretional Adjustment Type* (dropdown), Underlying Policy Number*, GC TIER* (dropdown), Tier Factor Number*, Crime Score*, and Operations Type* (dropdown) — note every field here is marked required (*) in this layout, unlike the old popup where most only became required after a dropdown was touched; then a "Named Storm" heading with Risk Company of underlying Property or Package that excludes Named Storm coverage*, Underlying Property or Package that excludes Named Storm coverage*, Building – Percent Completed (Builders' Risk Only)*, Building Code Effectiveness Grading (BCEG) Classification Code*, Named Storm Deductible*, and Named Storm Ded Min Per Occurrence* (dropdown). None of these were filled in this pass. This exact same set of fields also appears as the last step of the Commercial Property per-building wizard (see below) — it is not clear from the UI alone whether the two are the same underlying data or two independent copies; not confirmed.

Note: GL's old top-level "Limits/Deductibles" and "Additional Data" tabs (separate from the GL-specific Limits/Deductibles Of Insurance section) don't exist as their own breadcrumb steps any more — "Additional Data" now lives in the top-bar modal described above, and the risk-wide summary role is filled by the top bar's "Limit/Deductible Summary".

Commercial Property breadcrumb (coverage level)
Two steps: Building → Location (note the order — Building is listed first, opposite of General Liability's Location-before-Classification ordering). With no locations yet added, the Building step shows only "No Buildings Added"; you must use the Location step first to create at least one location, matching the old popup's model where a Building is always nested under a Location. Once a location exists, the Building step shows it as a "Location #1" card (with an aggregate TIV/Premium readout) containing an "Add Building" button and, once used, a nested building card with Edit/Copy/Delete actions. Clicking "Add Building" immediately creates a new Building record (auto-numbered "Building #1" — no dialog, no name to enter) and drops you into that building's own 5-step wizard (Classification, Limit & Deductible, Protective Devices, Scheduled Items, Additional Questions) — see `commercial-property-building.md` for the full walkthrough of that wizard, since it's substantial enough to keep as its own document.

The Location step itself is the same "Add New Location" form described under General Liability above (Copy Physical Address, Copy location(s) from, Address 1/2, City/State/Zip, Territory/County/Lat/Long, Description) — Commercial Property keeps its own independent location list, separate from General Liability's.

A UI quirk worth knowing: after using a top-bar action (e.g. Location Renumber) and closing its modal, the Building step can render a stale "No Buildings Added" message even though the building still exists — re-clicking away from and back onto the Building breadcrumb step refreshes it and shows the building correctly. Don't trust a "No Buildings Added" message immediately after closing a top-bar modal without re-navigating to confirm.

Closing the screen
"Close & Apply" (top right, always visible) closes the whole screen and returns to the Risk/Option Detail Angular page — but, as described above, it now runs a validation pass first and can block you with a "Confirmation List" of missing required data (e.g. "Classification details are required for each location in General Liability") rather than always closing unconditionally as the old popup did. There is no separate "Cancel"/discard action at the screen level beyond each step's own Cancel/Save Changes controls.

Full data-entry walkthrough, same instance (confirmed 2026-09-22, second pass — Commercial General Liability, submission SUB000860, quote CGL-BA-01, option NBS-1, Nautilus Insurance Group)
A later pass on this same "dyad" instance went beyond the earlier structural-only observation above and actually entered and saved real data through both sub-tabs for a General Liability risk. This confirms the two-sub-tab layout is fully functional for GL (the confirmed bug above is specific to the Commercial Property tab not swapping content — General Liability itself works normally end-to-end).

- "Limits/Deductibles" tab: filled General Aggregate, Products & Completed Operation Aggregate, Personal & Advertising Injury, Each Occurrence, Damage To Rented Premises, Medical Expense, and the Bodily Injury-Property Damage deductible as plain currency textboxes — straightforward. The Deductible Basis dropdown (right column) is a native `<select>` that does not behave like a normal clickable dropdown in this build: clicking it does not show a visible options list in a screenshot (native OS select popups don't render that way), and both the `find` and `read_page` tools returned no usable option list for it either. The reliable workaround: click the select to focus it (confirm via a zoomed screenshot showing a focus ring), then press the first letter of the desired option as a keyboard key (e.g. "p" → jumps to "Per Claim") — this uses the browser's native select type-ahead navigation. The same technique was needed again later for the Classification step's Exposure Base dropdown (see below) — treat any native `<select>` on this build that doesn't visibly respond to a click as a candidate for this same keyboard-focus-then-type-ahead approach.
- No "Include LAE" checkbox was found anywhere on the Limits/Deductibles tab in this pass, despite being present in some reference data sets for this screen — either it doesn't exist in this build, or it lives somewhere not yet located. Don't assume it's missing due to an entry mistake; treat it as an open item.
- Saving: the Additional Insured panel (embedded at the bottom of this same tab, as already documented above) has its own Save/Cancel pair, and a second Save/Cancel pair sits below the (usually empty) Additional Insured results grid further down. Clicking the first (Additional Insured) Save produced an "Insert Success" toast, and — as a side effect — silently unchecked the "Blanket Waiver of subrogation" checkbox that had been checked by default. Clicking the second/lower Save produced the toast that actually matters for confirming persistence: "**Limits/deductibles saved Successfully**" — this is the one to wait for/check for before trusting that the top Limits/Deductibles Of Insurance values were actually written, not the "Insert Success" one.
- "Location/Classification" tab, "Locations" grid: clicking "Add Location" opens a modal with a "Copy Physical Address" checkbox (separate from "Copy location(s) from" + Copy button, which copies from another location rather than the Insured's own address). Checking "Copy Physical Address" auto-filled Address 1, Address 2, City/State/Zip, and County correctly from the Insured's on-file address in this pass (a contrast to the breadcrumb-wizard instance's earlier finding that County sometimes didn't auto-fill — on this build/pass it did). Saving produced a "Risk location saved successfully" toast and the location appeared as row 1 in the grid.
- "Location/Classification" tab, "General Liability Classifications" grid: clicking "Add Classifications" opens a modal whose Location dropdown is pre-set to the just-added location. The ClassName field is a type-ahead: typing a partial description (e.g. "Dwellings") surfaced a real suggestion list (e.g. "(63010) Dwellings - 1 family (lessor's risk only)", "(63011) Dwellings - 2 family...", etc.) — typing the classcode number alone (e.g. "63010") did NOT surface suggestions, only searching by the description text did. Selecting a suggestion auto-filled ClassCode, ClassCode Desc, and Rate per, and defaulted Exposure Base to "Number" — which then had to be changed via the same click-to-focus-then-keyboard-type-ahead technique described above (pressed "e" to land on "Each"). After filling Exposure and Minimum Premium as plain textboxes and saving, the toast read "Risk saved successfully" and the classification appeared as a row in the grid beneath the location.
- Net effect: for General Liability on this build, the correct sequence is Add Location (with Copy Physical Address ticked, if the risk address matches the Insured's own) → save → Add Classifications (type-ahead by description, not code) → adjust Exposure Base via keyboard if it doesn't default to what's needed → fill Exposure/Minimum Premium → save. Both grids show their own running rows once saved, and there's no separate "Next" step — each Add-modal save is final for that row.
- "Close & Apply" on this build did not re-run the "Confirmation List" validation described above for the breadcrumb-wizard instance (e.g. it did not block on a Commercial Property location lacking Classification, since Commercial Property wasn't touched at all in this pass) — clicking it simply closed the ALIS.RD tab and returned focus to the Risk/Option Detail (`ALIS.BMS`) tab, where the Risk tab's data (Limits/Deductibles values, Location/Classification rows) was confirmed still present and correctly saved after the tab-close/refocus.
- What happens after Close & Apply — reaching an actual rated premium — is documented separately in `rate-summary.md`. Note: an earlier version of that document (and of this note) concluded that "Generate Quote"/"Generate Indication" on the Premium tab was the path to a rated premium and that it produced $0.00. That conclusion has since been corrected — see the "Confirmed end-to-end flow" section immediately below.

Confirmed end-to-end flow, this same instance (2026-09-22, third pass — submission SUB000861, quote CGL-BA-01, option NBS-1, Nautilus Insurance Group)
A further pass on this same "dyad" instance walked the full path from a blank risk to a rated premium showing on the Risk/Option Detail page, and corrects the "Generate Quote"/"Generate Indication" dead-end noted above. The sequence that actually works:
1. Add/Edit Risk (this document's flow above): Add Location (Copy Physical Address ticked) → save → Add Classifications (type-ahead by description) → correct Exposure Base via the keyboard type-ahead workaround if needed → fill Exposure/Deductible fields, taking care that a "Bodily Injury-Property Damage" deductible value goes into that specific field and not the plain "Property Damage" field (they are adjacent and easy to mix up) → Save on BOTH Save/Cancel pairs on the Limits/Deductibles tab, waiting specifically for the lower pair's "Limits/deductibles saved Successfully" toast, not just the upper "Insert Success" toast.
2. Close & Apply on the ALIS.RD tab — closes that tab and returns to the Risk/Option Detail (`ALIS.BMS`) tab. At this point the option row's premium box (next to the globe icon) and the right-hand Premium/Total Amount figures are still $0.00 — this step alone does NOT populate a rated premium. Generate Quote/Generate Indication are likewise not the way to populate it (see the note above) — skip both.
3. On the Risk/Option Detail page, click the small globe icon immediately left of the option row's "$0.00 →" premium box. This opens a new tab (`ALIS.Web.Custom/Rating/RateSummary.aspx?businessId=<N>`) that runs a live rating call and displays the full Rate Summary (Total Policy Premium, per-classcode rate table, carrier quote details) — see `rate-summary.md` for the full field reference, a caution that the rated numbers are not fixed constants, and a caution that this page can be flaky (slow loads, transient server errors, empty-result reloads) and worth retrying rather than treating as broken.
4. Click "Close & Apply" on the Rate Summary page (not on the ALIS.RD screen — a same-named but different button). This auto-closes the Rate Summary tab and writes the Classcode Premium back onto the Risk/Option Detail page: the option row's amount box and the right-hand panel's Premium/Total Amount fields update from $0.00 to the rated value (e.g. $79,347.00 in this pass). This is the step that actually makes the option show a non-zero premium — full details in `rate-summary.md`.

In short: Add/Edit Risk's own Close & Apply saves the risk data but does not rate it; rating and premium write-back happen entirely through the separate globe-icon → Rate Summary → Close & Apply flow documented in `rate-summary.md`.

CAUTION — clicking the UPPER of the two Limits/Deductibles Save buttons risked a real browser/tab freeze (2026-09-23 pass, submission SUB000862, quote CGL-BA-01, option NBS-1, Nautilus Insurance Group)
A further pass repeating this same end-to-end flow on a brand-new submission found a serious, reproducible problem with step 1 above: clicking the FIRST/upper Save button on the Limits/Deductibles tab (the one that saves the embedded Additional Insured panel and produces the "Insert Success" toast) twice caused the browser tab to stop responding entirely for 30–60+ seconds and then self-close, with none of the entered Limits/Deductibles data having persisted (confirmed by reopening Add/Edit Risk afterward and finding the fields blank). This happened on two separate attempts at re-entering the same data. Per explicit user instruction ("u see there r two save button click on below one in order to move further"), the fix is to click ONLY the LOWER Save button — the one that produces the "Limits/deductibles saved Successfully" toast. Re-entering the data a third time and clicking just the lower Save succeeded immediately with no freeze, and the save was confirmed to persist (checked by navigating away and back). This was then used for the rest of that pass (Location save, Classification save, Close & Apply) with no further freezes.
