Policy Generation / Review Policy (ALIS)

Overview
This is the flow for actually generating the policy document (a full policy-jacket PDF bundling every attached form) for a Bound option, and for catching a couple of classes of data problems before that document is produced: forms whose physical copy/template isn't loaded into the system, and forms that need extra data filled in to render correctly (e.g. a dollar/percentage pair for a Minimum Earned Premium endorsement). It's reached from the Bound-state Quote Option Detail page (see `quote-option-detail.md`'s "Confirmed — the richer Quote Option Detail layout only appears once an option is Bound" section) — this document assumes that page's context (Insured/Agency panels, right sidebar, bottom action bar) and only covers what's new once you leave it.

Reached via
Bound-state Quote Option Detail page → "Policy" link (top strip, next to Inspection/Certificate) → navigates to a "Quote" detail page (URL pattern `ALIS.BMS/APP/#/underwriting/quote/quote-list?data=<encoded>` — despite the URL saying "quote-list" this is a single option's detail view, the same Bound-state layout documented in `quote-option-detail.md`) → bottom action bar → "Review Policy" button → opens a NEW BROWSER TAB at a separate legacy ASP.NET page, URL pattern `ALIS.Web.Custom/IPG/PolicyMissingValues.aspx?businessId=<N>&IsRevoked=0` (same `businessId` used elsewhere for this option's Rate Summary page — see `rate-summary.md` — confirming it's the same internal option/business-transaction ID throughout the app). Despite the URL/page title being "Policy Missing Values" / "Policy Generation", this single page walks through multiple sequential tabs as you click through it, described below in the order they appeared.

Tab 1 — "Schedule of Forms" (always present)
A read-only grid, no page heading beyond "Policy Generation" / "Schedule of Forms", columns Form No. / Form Name / Version, one row per form currently attached to the option — i.e. this should exactly mirror the Quote Option Detail's own Terms & Forms "Forms" grid (see `quote-option-detail.md`), and is a reliable independent way to cross-check that grid's count/contents. Confirmed (2026-09-23, SUB000863-01): after the Terms & Forms tab showed "Forms [Count: 28]", this Schedule of Forms tab listed exactly 28 rows, form-for-form identical to the Terms & Forms grid.

Tab 2 — "Missing Forms" (conditional — only appears if at least one attached form has no physical copy/template loaded)
Heading "Physical copies for below Forms are missing. Please contact administator." [sic — typo present in the live UI text] above a "Missing Versions" grid (Form No. / Form Name / Version) listing just the affected form(s), and a "Close" button (no Continue on this tab itself). Confirmed (2026-09-23, SUB000863-01, businessId=3610): with the state-specific auto-attached form IL 02 60 ("CONNECTICUT CHANGES-CANCELLATION AND NONRENEWAL", 01/26) still attached, this tab appeared and flagged exactly that one form. This is a genuinely useful signal, not just a data-quality warning to ignore: per explicit live instruction, a form flagged here should be deleted from the option (back on the Quote Option Detail page's Terms & Forms tab — see the deletion workflow in `quote-option-detail.md` — then Save), after which re-opening Review Policy no longer shows a "Missing Forms" tab at all (only "Schedule of Forms" remained, now listing one fewer row). Practical guidance: treat an appearance of this tab as "this form needs to be removed from the option," not as a benign warning to click past — but don't assume it's exhaustive; the target form count is whatever the "should be present" reference list's own item count is (see `quote-option-detail.md`), and this tab is a helpful check, not the sole source of truth for which forms are extra.

Bottom of Schedule of Forms — "Select Copy Type" and "Continue"
Below the forms grid (whether or not a Missing Forms tab is present): a "Select Copy Type" checkbox group — Insured / General Agent / Company / Broker / State / Additional Interest (Insured is checked by default; the others were left unchecked and not exercised this pass) — determining which recipient(s) get a generated copy later in the flow, then a separate "Duplex Printing" checkbox (unchecked/not exercised), then "Continue" and "Close" buttons.

Tab 3 — "Missing Values" (conditional — only appears if an attached form needs data that hasn't been supplied elsewhere in the option)
Clicking "Continue" from Schedule of Forms can reveal this tab instead of proceeding straight to Recipient Copies. Heading "Missing Details" above a two-column grid: a plain-English field label (naming the form's code in parentheses) on the left, an empty text input on the right. Confirmed (2026-09-23, SUB000863-01): with form S013 ("Minimum Earned Premium Endorsement") attached, this tab showed two required fields — "Minimum Earned Premium In Dollar(S013)" and "Minimum Earned Premium In Percentage(S013)" — both blank text inputs, no format hints or validation borders observed. These are genuinely form-specific: a different attached form needing its own fill-in data would presumably show its own differently-labeled field(s) here instead/in addition (not confirmed with a second example this pass). Values used this pass (supplied by explicit live instruction, not inferred): 525.5 (dollar field, entered as plain "525.5", no "$" typed) and 13 (percentage field, entered as plain "13", no "%" typed) — both accepted with no reformatting observed in the field itself. A "Continue" button sits below the grid.

Tab 4 — "Recipient Copies" (terminal tab — this is where the actual PDF is produced)
Heading "Recipient Copies" above a grid: one row per recipient checked in "Select Copy Type" earlier (this pass had only "Insured" checked, so exactly one row, labeled "Insured"), with four per-row action icons — "Save as Image", "Save as PDF" (a red PDF icon), "Email" (envelope icon), "Print Queue" (printer icon) — and a "Close" button. The recipient's own name/label (e.g. "Insured") is itself a clickable link.

Clicking the recipient link (e.g. "Insured") opens a NEW BROWSER TAB with the actual generated policy-jacket PDF, served directly (not through a viewer/preview page) at a URL of the form `ALIS.Web.Custom/IPG/PolicyJackets/<CompanyCode>/<SubmissionQuoteCode>/<Recipient>Copy-<M>-<D>-<YYYY>_<h>-<mm>-<ss>_<AM|PM>.pdf` — confirmed example: `.../PolicyJackets/DM_DEMO/SUB000863-01/InsuredCopy-9-23-2026_5-33-31_AM.pdf`. This is a real, timestamped, generated file (not a live/cached template render) — whether repeating this action produces a new timestamped file each time or reuses one from earlier in the same session was not tested.

The generated PDF — structure and verification
For this pass's option (28 attached forms, CGL/Artisan Contractor, CT risk), the generated PDF was 49 pages — i.e. NOT one page per form (28 forms ≠ 49 pages); some forms clearly render as multiple pages (e.g. full coverage forms like the CGL Coverage Form itself), so page count isn't a simple proxy for form count. Page order does NOT match the Terms & Forms grid's own row order and does not appear alphabetical either — page 1 of this PDF was the "Limited Swimming Pool Pop-Up Liability Coverage" form (i.e. one of the L-series exclusion/limitation endorsements), not the policy jacket/declarations page or any obviously "first" form; the actual ordering rule wasn't determined this pass (worth checking "Reorder forms" on the Terms & Forms tab, which was never exercised — see `quote-option-detail.md`'s open items — as a possible source of whatever order this is).

Verification workflow used and confirmed correct (2026-09-23, SUB000863-01): rather than reading the PDF page by page from the start, jump directly to a known page via the PDF viewer's own page-number field (Chrome's built-in PDF viewer — click/triple-click the page-number box at the top of the toolbar, type the target page, Enter). The form needing Missing Values data (S013) rendered on page 23 of 49 this pass; its exact page number is specific to this option's form list/order and shouldn't be assumed to hold for a different option. On that page: the "POLICY NUMBER:" field at the top of the form printed the exact value entered in the Bind & Invoice modal (`POL863260923092853`), and the Minimum Earned Premium paragraph rendered both Missing Values fields inline in their sentence ("...there will be a minimum earned premium retained by us of $525.5 or 13 % of the premium...") with the exact values entered, correctly substituted into the sentence with no truncation, reformatting, or visual overlap between the inserted values and the surrounding static text.

Minor cosmetic finding — pre-existing template gap, not a data-overlap bug
The S013 form's own printed title in the generated PDF reads "MINIMUM EARNED PREMIUM EN   DORSEMENT" (visible extra gap, missing the "N" that would complete "ENDORSEMENT"). Zoomed inspection confirmed this is baked into the form's own static title text — unrelated to, and not caused by, the two inserted Missing Values (which render correctly elsewhere on the same page, described above). Most likely a pre-existing typo/spacing defect in this carrier's own form template, not a rendering bug in ALIS's PDF generation step. Worth a quick sanity check on other forms/other passes to see if this is specific to this one template or symptomatic of a broader template-rendering quirk, but it is NOT the kind of data-overlap issue that would indicate the two Missing Values fields were plugged in incorrectly.

Confirmed a second time, independent pass (2026-09-23, SUB000864-01, businessId=3611): the S013 "Missing Details" step again showed exactly the same two fields (Dollar / Percentage), filled with the same test values (525.5 / 13) for consistency with the reference pass; the PDF was again 49 pages for a 28-form option (same form count as the reference pass, same page count — consistent, though the two passes' form lists weren't byte-for-byte identical so this may be coincidental rather than a fixed form-count→page-count ratio); the S013 form landed on the same page 23 of 49 as the reference pass. Both the "MINIMUM EARNED PREMIUM EN DORSEMENT" title gap and the correctly-substituted Missing Values sentence reproduced exactly as before, reinforcing that the title gap is a fixed template defect, not something tied to a specific option's data.

New finding this pass — a long Policy Number wraps across two lines in the PDF's "POLICY NUMBER:" field, with no data loss
This pass's Policy Number (`POL000864260923102114`, 21 characters — longer than the reference pass's 18-character `POL863260923092853`) rendered on the S013 page's "POLICY NUMBER:" line as two stacked lines — `POL000864260923102` on the first line, `114` continuing directly below it — rather than the single line seen in the shorter reference example. Zoomed character-by-character comparison against the exact string typed into the Bind & Invoice modal confirmed this is a pure visual line-wrap (the field's rendering box has a fixed width and wraps overflow text onto a second line) with NO truncation, character substitution, or data loss — all 21 characters were present and in the correct order across the two lines. Don't be alarmed by a wrapped Policy Number in the generated PDF; do zoom in and verify the full string reads back correctly across the wrap, the same verification standard used for any other injected value on this page.

This pass also reconfirms the Terms & Forms → Schedule of Forms cross-check works as a recovery-verification tool: after remediating an accidental extra deletion (see `testing-process-notes.md` Rule 10 and `quote-option-detail.md`) by re-adding the wrongly-deleted form via the "Add Forms" modal, this pass's Schedule of Forms tab showed exactly 28 rows again, with the re-added form (CG0001) present as the LAST row in the list (consistent with the "Add Forms" modal appending rather than reinserting at original position, per `testing-process-notes.md` Rule 10) and none of the 10 intentionally-deleted forms reappearing — confirming the Review Policy flow's Schedule of Forms reads live from whatever the Terms & Forms tab currently holds, not a stale/cached snapshot from before the remediation.

Confirmed workflow, start to finish (2026-09-23, SUB000863-01, businessId=3610)
Bound-state Quote Option Detail → "Policy" link → "Review Policy" → (if a Missing Forms tab appears) delete the flagged form(s) from Terms & Forms, Save, re-open Review Policy → Schedule of Forms shows only "should be present"-list forms, count matches the reference list exactly → "Continue" → (if a Missing Values tab appears) fill in every required field with the values supplied for this test pass → "Continue" → Recipient Copies shows one row per selected copy type → click the recipient's own name link → new tab opens the generated PDF → jump to the page(s) containing injected/variable data (Policy Number, any Missing Values fields) and zoom-verify the values and surrounding text render correctly with no overlap.
