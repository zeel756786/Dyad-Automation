Rate Summary — Confirmed Flow & Field Reference (ALIS)

Overview
"Rate Summary" is a read-only, carrier-rated premium breakdown for a Quote/Option: a "Total Policy Premium", a per-location/per-classcode rate table (Exposure/Exposure Base/Prem Rate/Prod Rate/Final Rate/Classcode Premium), and carrier-side quote details (Quote Number, Quote URL, Coverage Highlights, Carrier Request/Response XML). This document supersedes an earlier version of itself that concluded the rating flow was broken/unreproducible on this "dyad" instance (`https://customer-alis.dyadtech.com`, v4.1.19.5) — that conclusion was wrong. The correct entry point (below) was found and confirmed end-to-end on 2026-09-22, on a freshly created submission, with every rating-engine-computed value matching a previously-provided reference example exactly.

The correct entry point (confirmed)
On the option row of the Risk/Option Detail page — the same row showing "NBS-1", the Risk Co./Market Co. names, Fees, Taxes — there is a small globe icon sitting directly left of the "$0.00 →" premium box. Clicking it opens a brand-new browser tab at a URL of the form:
`https://customer-alis.dyadtech.com/ALIS.Web.Custom/Rating/RateSummary.aspx?businessId=<N>`
— `businessId` is a numeric ID specific to that option/business (e.g. `3608` in this pass); it will differ per option and is not predictable in advance. The new tab's page title is literally ".:: Rate Summary ::.". The tab shows a brief "Page Load" indicator at the very bottom while it computes/fetches the rating, then renders the full summary — in this pass this took only a second or two, not long enough to require an explicit wait/poll loop, but budget a couple of seconds before reading the page just in case.

Important correction to the previous version of this document: no "Generate Quote" / "Generate Indication" click, and no TRIA Premium / Agent Comm % pre-filling on the Premium tab, is required to see a populated Rate Summary. This globe-icon path computes and displays the real rated premium directly, on demand, independent of those Premium-tab fields and buttons. The earlier finding that Generate Quote/Generate Indication "completed with no error but left Premium/TRIA/Fees/Tax at $0.00" is still accurate as a description of what THOSE buttons do (they don't populate the Risk/Option Detail page's own summary numbers) — it was simply the wrong place to look for the rated premium. The globe icon is the right place.

Other candidate entry points that did NOT work (kept for reference, so they aren't retried)
- Premium tab's "⋮" (kebab) menu → "Web Rating Details" — opened a blank `about:blank` tab that never rendered. Not the right path.
- "DQS" link on the Premium tab — no visible effect.
- Generate Quote / Generate Indication buttons — run without error but do not themselves surface the Rate Summary or update the Risk/Option Detail page's Premium/TRIA/Fees/Tax figures; the globe icon is a separate, independent computation.

The Rate Summary page — layout
Top strip: "Quick Print" link (left), "Expand Summary" / "Collapse Summary" toggle link (right — the wording flips depending on state; clicking it did not visibly change what was on screen in this pass since there was only one location/classcode to show, so its effect with multiple locations is unconfirmed). Below that, an "Rate Summary" heading, then a policy-info row: Named Insured, Quote Number, Effective Date, Expiration Date (left-aligned), and a "Rating Date : <timestamp>" on the right.

Below that, one card per Risk Company on the option: a header row with "Risk Company" / the company name on the left and "Total Policy Premium" / its dollar value on the right (with a −/+ collapse icon for that card — collapsed state not exercised), then "Policy Minimum Premium : <value>" and "Total Policy Premium : <value>" repeated as plain text under the header. Below that, one block per coverage/location: a coverage name heading (e.g. "Commercial General Liability"), "Location No.<n>" and its full address, then a table with columns Classcode / Exposure / Exposure Base / Prem Rate / Prod Rate / Final Rate / Classcode Minimum Premium / Classcode Premium — one row per classification on that location. Below the table: "Quote Number : <carrier quote #>", "Quote URL : <link>", "Website : <link>", a "Coverage Highlights:" bulleted list, and a "Carrier Request(s) / Response(s):" section with "Request XML" / "Response XML" links (both present as clickable blue links in this pass; their actual content was not opened/inspected). Bottom of the page: "Close & Apply" and "Close" buttons — "Close & Apply" is now confirmed (see "Close & Apply — confirmed effect" below); "Close" was not exercised.

Close & Apply — confirmed effect
Clicking "Close & Apply" does two things: (1) it closes the Rate Summary tab automatically and returns focus to the underlying Risk/Option Detail tab — no manual tab close is needed; (2) it writes the rated premium back onto the Risk/Option Detail page in two places: the small amount box next to the globe icon on the option row (previously "$0.00 →", now "$79,347.00 →"), and the right-hand summary panel's "Premium" field (previously $0.00, now $79,347.00), which also flows into "Total Amount" there (Premium + Fees + Taxes — in this pass $79,347.00 + $300.00 + $2,386.41 = $82,033.41).

Note the value written back is the Classcode Premium ($79,347.00), not the Total Policy Premium shown at the top of the Rate Summary card ($79,397.00, the $50 higher figure that includes the unitemized fee noted in the verification section below). Don't be surprised if the option row's premium and the Rate Summary's "Total Policy Premium" differ by a small amount for this reason — they are reading different fields, not disagreeing.

Caution for future passes — treat rated values as a moving target, not a fixed constant
The $79,397.00 / $79,347.00 / 79.347 rate figures verified here are specific to the exact risk data used in this pass (this classcode, this exposure amount, this state/location, this carrier). They are NOT a universal constant of the ALIS system — carriers periodically update their own rate tables, and any change to the underlying risk data (different Exposure, different classcode, different location/state, different carrier/market) will legitimately produce different rated numbers. When verifying a Rate Summary against a previously-recorded reference in the future: (1) confirm the risk INPUT data matches (classcode, exposure, location/state, carrier) before treating a premium mismatch as a bug — a genuine rate-table change on the carrier's side is a valid explanation, not just tester error; (2) expect the submission-specific fields listed above (dates, quote numbers, named insured) to always differ and don't flag those; (3) if a future value differs from what's recorded here for the SAME input data, note the new value alongside the old one with the date observed, rather than overwriting this record outright, so a genuine rate-table change is visible as a trend rather than silently lost.

Reliability caution — the Rate Summary page can be genuinely flaky (not a scripting bug)
Every open/reload of the Rate Summary page re-runs a LIVE rating call against the carrier (it is not cached), and across repeated attempts in one session this call showed at least four different behaviors: (1) fast success, data visible in ~2-3s; (2) success but only after a longer wait (~15-20s or more); (3) an explicit failure — a collapsible "Errors" section reading "Nautilus Insurance Group: Ratinghub Error - Error - Internal Server Error"; (4) an anomalous empty result — just the bare policy-info header row, no Risk Company card, no Total Policy Premium, no classcode table, with "Expand Summary" implying there's nothing to expand. This looks like genuine carrier/rating-hub instability on the backend, not a UI defect. Practical guidance for future passes: don't conclude the flow is broken from one bad load — reopen the page (via the globe icon, or by navigating directly to the known `RateSummary.aspx?businessId=<N>` URL) and give it up to ~20-30 seconds before deciding it's stuck or erroring; treat an "Internal Server Error" or empty-result screen as a reason to retry, not as proof the rating itself failed (in this session, an apparently-empty/erroring reload was followed shortly after by a fully successful Close & Apply that correctly updated the Risk/Option Detail page — see above). If a click on "Close & Apply" itself seems to hang or produce a blank page, check the underlying Risk/Option Detail tab before re-clicking anything — the write-back may already have succeeded even though the Rate Summary tab's own confirmation was hard to observe.

A further pass (2026-09-23, submission SUB000862, businessId=3609) saw a fifth, worse failure mode not previously catalogued: the page hung on its own "[Please wait...]" loading indicator indefinitely — no data, no error, no empty-result screen — for 30+ seconds on two separate full open/close/retry attempts (each via the globe icon). Unlike the "Internal Server Error" or empty-result modes above, there was no signal at all that the attempt had failed; it simply never resolved within a reasonable wait. A third attempt (same globe-icon → open sequence) succeeded after roughly another 30 seconds. This reinforces the existing guidance to retry rather than assume the flow is broken, but raises the practical retry budget: for this instance, be prepared to close and reopen via the globe icon up to 3 times, and don't treat a silent "[Please wait...]" hang under ~30s as evidence of failure on its own.

A third pass (2026-09-23, a from-scratch restart, submission SUB000863) surfaced a sixth failure mode, distinct from all the above: an explicit "Ratinghub Error - Http/1.1 Service Unavailable" for Nautilus Insurance Group, shown in the page's own collapsible "Errors" section (which also had a "Carrier Request(s)/Response(s)" section showing the actual request XML sent to the carrier). This error state has its own dedicated "Page Load" button for retrying — distinct from a full browser reload/re-navigation, and this pass used it to retry in place rather than closing and reopening via the globe icon. Overall reliability this pass was markedly worse than any previously documented occurrence: reaching a successful load took roughly 5 total retry attempts, mixing plain hangs, blank/empty reloads, and this new explicit Ratinghub error, spanning several minutes before the rate table finally populated. The underlying rating calculation itself was unaffected by this instability — the same Bethel, CT / classcode 63010 / Exposure 1,000 input that produced $410,115.00 in the SUB000862 pass above produced the identical $410,115.00 again here, a third confirming data point that the rate-table output is stable even when the page's own loading/retry behavior is not. Practical addition to the guidance above: when an "Errors" section appears with a carrier-specific service-unavailable message, use that section's own "Page Load" retry button first before falling back to a full close/reopen via the globe icon.

Second worked example, different location/state — confirms rated figures are location-dependent, not fixed (2026-09-23, submission SUB000862, quote CGL-BA-01, option NBS-1, businessId=3609)
A fresh submission with the SAME classcode and exposure as the reference above (63010, Exposure 1,000, Exposure Base "Each" entered / "T" displayed) but a DIFFERENT risk location/state (139 Southeast Main Street, Bethel, CT, 06801, Fairfield County/Territory 507 — vs. the reference's Larue, MS) produced substantially different rated figures: Prem Rate 410.115, Prod Rate 0, Final Rate 410.115, Classcode Premium $410,115.00, Total Policy Premium $410,115.00 (Risk Company: Nautilus Insurance Group). This is roughly 5x the reference example's $79,347.00 for the identical classcode/exposure — correctly attributed to the different risk location/state, per this document's own "Caution for future passes" below, and not a bug or regression. Also note this pass's Total Policy Premium matched its own Classcode Premium exactly (no small itemized-fee gap, unlike the reference example's $50 difference) — another data point suggesting the gap between these two figures isn't constant either and shouldn't be assumed present. Close & Apply wrote this premium back correctly: option row Premium $410,115.00, Fees $300.00, Taxes $16,408.60, Total Amount $426,823.60.
