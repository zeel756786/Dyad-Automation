Quote Option Detail — Risk / Premium / Terms & Forms (ALIS)

Overview
This is the screen reached by clicking an option's premium amount link (the "$79,347.00 →" box, or "$0.00 →" before anything is rated) on the Quote tab's option row — see `market-selection.md`, "Result: the option row", which flagged this screen as not yet documented. URL pattern: `ALIS.BMS/APP/#/underwriting/quote/options?data=<encoded>`. It is the same screen referred to elsewhere in this knowledge base as the "Risk/Option Detail page" (see `rate-summary.md` and `add-edit-risk.md`), documented here in full for the first time. It shows everything about one option on one quote — the risk data entered via Add/Edit Risk, the rated premium, the policy forms, and a few other tabs — and is where Close & Apply (on the separate Rate Summary popup, not this screen) ultimately writes the rated premium back to.

Reached via
Submission → a quote tab (e.g. "CGL-BA-01") → the option row's premium amount link (e.g. "$79,347.00 →", to the right of the option's Fees/Taxes figures and left of the kebab "⋮" menu) → this page opens in the same tab, replacing the option-row view. A "← Back to List" link (top right) returns to the quote/options list.

Header (always visible, above the tabs)
Risk Company (heading) and, below it, Market Company / Coverage / COB — then, right-aligned in the same strip: Premium, TRIA, Fees, Tax, "Total Amount w/o TRIA", and Total Amount. Top-right of the header: "← Back to List", a globe icon (opens the Rate Summary popup — see `rate-summary.md`), and a "⋮" kebab menu (Copy Option / Delete / Web Rating Details — the last of these is a dead end, see `rate-summary.md`'s "did NOT work" section). Before any risk/rating data exists, Premium/TRIA/Fees/Tax/Total Amount all read $0.00; after a risk is entered and Close & Apply is completed on the Rate Summary popup, these populate with the rated figures and stay in sync with the option row's own premium box.

Tabs: Risk, Premium, Terms & Forms, Additional Interest, Other Details
Clicking a tab shows a brief spinner before the new tab's content replaces the previous tab's — the previous tab's data stays visible under the spinner for a moment, so don't screenshot too early and assume the click didn't register (the same caveat noted for the Add/Edit Risk breadcrumb in `add-edit-risk.md`).

Risk tab (default)
A heading naming the coverage and its premium in brackets (e.g. "COMMERCIAL GENERAL LIABILITY [ $79,347.00 ]"), a "Refresh Risk Summary" button, and "Add/Edit Risk" (top right — opens the ALIS.RD screen documented in `add-edit-risk.md`). Below that: the coverage name again, then a two-column read-only table — Limit (General Aggregate, Products & Completed Operation Aggregate, Personal & Advertising Injury, Each Occurrence, Damage To Rented Premises, Medical Expense, Professional Limit) and Deductible (whatever deductible fields were actually filled — e.g. just "Bodily Injury-Property Damage" if that's the only one entered) — mirroring exactly what was saved on the Add/Edit Risk screen's Limits/Deductibles tab. Confirmed (2026-09-22): every value here matched the Add/Edit Risk entry exactly, field for field, with no transformation or rounding.

Premium tab
Heading "Rated Premium : $<amount>" with a copy icon. Fields: Premium $ (a "Premium Distribution" dropdown next to it — Annual/Flat/M&D/MP/MSR/Term/--Select--, not exercised), TRIA Type (Applied/Included/Not Applicable/Rejected), TRIA Premium $, Fees $ (with a "Load from Admin" refresh icon), Taxes $ (same), an "Exempt" checkbox, Gross Comm % (shows "[GLOBAL DEFAULT]" and a dropdown of commission-agreement options), Agent Comm % (dropdown: Special Agency Commission / the agency code / GLOBAL DEFAULT), MEP (with a $/% toggle), CoInsurance %, Filing State (text, plus a "Multi State" checkbox), Billing Type (Agency Bill / Direct Bill to Company / Direct Bill to Insured / Direct Bill to Lien Holder / -SELECT-), Filing Entity (Agency file / Company file / Courtesy file / MGA file), a "Courtesy-Invoice Taxes Only" checkbox, Quote Expiration Date, BOR Policy / Non-Recurring / Auditable checkboxes, and Reason / Note free-text fields. Right side: DQS / Contract / Finance links (not exercised). Confirmed (2026-09-22): after a successful Rate Summary → Close & Apply (see `rate-summary.md`), this tab's "Rated Premium" and "Premium $" both read the Classcode Premium from the Rate Summary, and Fees $/Taxes $/Gross Comm % matched the values already shown in this page's own header and the option row.

Terms & Forms tab
Two independent grids, "Forms [Count: N]" and "Terms [Count: N]" (Terms was empty — 0 — in every pass so far). Each has its own "Add More Forms" / "Add More Terms" button. The Forms grid has columns Form No. (a link, opens the form document), Form Name, Version, Delete (a checkbox per row), and Form Remarks; above the grid: "Reorder forms", "Load From Admin", "Delete Form" (red), and "Add More Forms" (green) buttons.

IMPORTANT — the Forms grid under-renders on a large mouse-wheel scroll; use small scroll steps and trust the Count header, not what you've counted by eye
The Forms grid is virtualized (only rows near the current scroll position exist in the DOM at any moment — confirmed both in the main grid and in the "Reorder forms" modal, which is the same virtualized list in a popup). Scrolling by a large amount in one action (5+ mouse-wheel ticks) can jump clean over a whole screenful of rows without ever rendering them, so a manual tally built from a handful of large-increment scroll-and-screenshot steps will silently under-count — in one pass this cost 8 real rows (a 38-row list first appeared to be only 30 rows long). Re-scrolling with small steps (2–3 ticks at a time), and overlapping each screenshot with the last few rows of the previous one so no row-range is skipped, found the missing rows and reconciled the count exactly. Practical rule: always trust the "Forms [Count: N]" heading as the ground truth for how many rows exist, and if a manual scroll-through doesn't add up to that number, re-scroll in smaller steps rather than concluding the extra rows don't exist or that the header count is stale. Pressing End after clicking a cell in the last visible row is a reliable way to confirm you've truly reached the last row (it won't reveal skipped rows in the middle, only confirm the bottom).

Deleting forms — confirmed workflow
Tick the checkbox in the Delete column for each form to remove (multi-select — ticking one row highlights it blue and does not affect the others), scrolling as needed with the small-step technique above to reach forms anywhere in the list; checked rows stay checked/highlighted as you scroll away and back. Once all the intended rows are ticked, click the red "Delete Form" button (top of the grid, not per-row) — this raises a "Please Confirm" / "Are you sure you want to delete?" dialog with Cancel/Ok. Clicking Ok deletes all ticked rows in one action and immediately updates the "Forms [Count: N]" heading — no separate page-level Save was needed for the deletion itself to take effect in this pass, and it survives a full page reload (confirmed by reloading afterward and finding the same lower count and the same rows gone), so it's a real server-side delete, not just unsaved UI state.

CAUTION — clicking anywhere on a form's row can silently tick its own Delete checkbox, not just clicking the checkbox itself
Confirmed by reproducing it: clicking on a row's Form Name text (nowhere near the Delete column) toggled that row's own Delete checkbox on. This is easy to trigger by accident while clicking a row to focus it for keyboard navigation (e.g. to press Home/End to jump to the top/bottom of the virtualized list — see the scrolling caution above), and it's dangerous specifically because it's silent: nothing indicates a checkbox changed unless you scroll back and look. Before clicking "Delete Form", always scroll back through the whole list one more time and visually confirm every ticked row is one you actually intended to delete — don't trust a running mental tally, and don't click on a row for any reason (including just to click a Form No. link, or to click-then-press-Home/End) without re-checking its Delete box state afterward.

A live example of what happens when this caution isn't heeded, and how to recover (2026-09-23, SUB000864-01, an independent fully-autonomous pass with no step-by-step user guidance): the row-click-toggles-checkbox trap (above) actually caused a real over-deletion this pass, not just a near-miss. A stray click made to defocus/click blank space (unrelated to any intended checkbox change) landed on the CG0001 row ("CGL COVERAGE FORM," the option's own base coverage form — not one of the 10 forms meant to be deleted) and silently ticked its Delete checkbox; this went undetected because the checkbox column wasn't re-screenshotted immediately before clicking "Delete Form," and CG0001 was deleted alongside the 10 intended forms, dropping the count to 27 instead of the correct 28. This was only caught afterward, by comparing the post-deletion row-by-row list against the expected 28-item "should be present" reference list and noticing CG0001 was missing from between S013 and CG2147 (where it had previously sat). Recovery did not require re-doing the whole deletion pass — it was fixed forward, in place, using the "Add More Forms" modal (Advanced Filter → Form Code "Contains" → the exact code → Search → tick its row → "Add To Quote"; full step-by-step in `testing-process-notes.md` Rule 10), which restored the count to 28 with CG0001 correctly back in the grid (appended as the last row, not reinserted at its original position) and none of the 10 intentionally-deleted forms reappearing. Net lesson: the checkbox-column re-verification step immediately before clicking "Delete Form" isn't optional caution, it's the only thing standing between a stray focus-click and a genuine, silent over-deletion of a form that was never meant to be touched — and if it does happen anyway, it's recoverable without starting the option over.

Caution for future passes
As with Rate Summary (`rate-summary.md`), don't treat the exact form list, form versions, or which forms are auto-attached as fixed constants — carrier form libraries change over time (form version dates like "02/26" or "07/26" already point at future review/reissue dates from this session's own vantage point, which is normal for how carriers pre-date form revisions). Re-verify the actual attached list against whatever reference is current at the time, rather than assuming this document's 38/29-count breakdown will still apply.

Agent Comm % is a custom dropdown, not a native `<select>` (confirmed 2026-09-23)
Unlike TRIA Type (a genuine native `<select>`, directly settable via the `form_input` tool once located with `find`), the Agent Comm % field on the Premium tab is a custom-built dropdown: it has no native option list a browser-automation `form_input` call can target. The reliable approach: use `find` to locate its "Toggle Dropdown" button (separate from the field's own displayed value), click it to reveal a real overlay listing the available choices (in this pass: Special Agency Commission / the agency's own code / GLOBAL DEFAULT), then click the desired option directly in that overlay. A direct mouse click on the overlay option worked correctly.

Revised standing rule for future passes: after bulk-deleting the reference "should be removed" forms, don't assume any remaining unflagged form is fine to leave — the actual target is the reference "should be present" list's own count (28 in this classcode/COB), and any extra auto-attached form beyond that (state-specific cancellation/nonrenewal forms like IL 02 60/IL 02 82 are the ones seen so far) should also be deleted.
