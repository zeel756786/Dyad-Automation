Commercial Property — Building-Level Data Entry (ALIS)

Overview
Once a Location has been saved on the Add/Edit Risk screen's Commercial Property → Location step (see `add-edit-risk.md`), the Commercial Property → Building step shows that location as a card with an "Add Building" button. Clicking it immediately creates a new Building (auto-numbered, no name/dialog to fill in) and drops you into a 5-step wizard — Classification, Limit & Deductible, Protective Devices, Scheduled Items, Additional Questions — where the actual insurable values (limits, deductibles, construction/classification detail) are entered. This document covers that Building-level wizard only; the Location step itself, and everything else on the Add/Edit Risk screen, is covered in `add-edit-risk.md`.

As of this pass (2026-09-16) the Add/Edit Risk screen (and this Building wizard) runs in a new Angular app (`ALIS.RD`), replacing the legacy ASP.NET popup described in earlier versions of this document. The two-tab "Property Information" / "Optional Coverage/Limits/Deductibles" layout from the old popup no longer exists — it has been split into the 5-step wizard described below. Everything in a prior version of this document about a page-level Save button guarding against data loss on tab-switch, or about a separate Optional Coverage sub-form with its own Save-hang bug, is superseded (neither issue was reproduced under the new UI, see "Behavior / callouts" below).

Layout once a Building is added
Clicking "Add Building" creates "Building #1" (numbering is automatic) and immediately opens its own step wizard, shown as a breadcrumb-style nav above the Location/Building summary card: Classification (a version number is shown next to this step's label, e.g. "Classification 718" — this looks like an internal build/config version stamp rather than anything the user sets) → Limit & Deductible → Protective Devices → Scheduled Items → Additional Questions, joined by dashed progress lines that fill in green as you move forward. Above the step content, a persistent card shows the Location and Building ("Location #1" / "Building #1", with the building's address, a small static map thumbnail, and read-only Distance to Coast/Construction Type/Year Built/Sq. Ft./#Of Families/Protection Class/#Of Stories placeholders that populate once the Classification step's fields are filled in) plus running TIV and Premium totals and a "Delete Building" button. Each step has Previous/Next buttons at the bottom (the first step has no Previous; the last step, Additional Questions, has no Next — only Previous).

Behavior / callout — Next auto-saves each step
Unlike the old popup (where a page-level Save button had to be clicked before navigating away, or edits were silently discarded), clicking "Next" on this wizard saves the current step immediately — confirmed by a "<Step Name> has been saved successfully" toast appearing after every Next click (e.g. "Classification has been saved successfully", "Limit/Deductible has been saved successfully", "Protective Devices has been saved successfully") before the next step's content loads. Stepping all the way through to Additional Questions and leaving the browser tab (without an explicit final "Save" click, since the last step has none) still left the Building intact when re-checked. The old popup's "don't switch tabs before clicking page-level Save or you'll lose your edits" caveat no longer applies.

Behavior / callout — stale "No Buildings Added" after a top-bar action
After using one of the Add/Edit Risk screen's top-bar actions (e.g. Location Renumber) and closing its modal, the Building step can render a stale "No Buildings Added" message even though the Building still exists underneath. Re-clicking away from and back onto the Building breadcrumb tab refreshes the view and shows the Building correctly. Don't take "No Buildings Added" at face value immediately after closing a top-bar modal — re-navigate to confirm before concluding data was lost.

Classification step
This step covers both the identity/classification of the building and its physical construction details (the old popup split these across "Property Information" and part of "Building Improvements/Updates" — here they're one step):
- A "Property Info" panel (labelled with a version number, e.g. "Property Info 039"): ClassName, CSP Code (greyed, presumably auto-filled from ClassName the same type-ahead way as the old popup — not independently re-tested), Nautilus GL Classname dropdown, Classification Description, Construction... (a field whose label is truncated in the UI), Protection Class dropdown, Construction type dropdown, Year Built dropdown, Sq. Ft., #Of Stories, Home No., No. of Families, Unit No., Distance to Coast dropdown, Distance to Tidal Water.
- A "Building Improvements" panel: Wiring Year / Roofing Year / Plumbing Year / Heating Year dropdowns (each with its own Full/Partial checkboxes), Other Year, Roofing Material, Roofing Style dropdowns, Occupancies dropdown, "Vacant Since:(in months)" dropdown, Vacant Since Date (a calendar-icon date field), Building Code Grade, Tax Code, a "Ground Floor" checkbox, Wind Class dropdown, Roof Age, Right/Left/Front/Rear Exposure and Distance fields, and Yes/No/None radio triplets for Swimming Pool, Hot Tub, Approved Fence, Exotic or Dangerous Pet Breed, Diving Board, and Storm Shutter Fitted (all default to None).
Neither Protective Devices fields nor the ClassName type-ahead's suggestion-list behavior were re-exercised in this pass (the old popup's documented behavior — typing a partial class name shows "(<CSP code>) <full name>" suggestions that fill CSP Code and Classification Description — is assumed still applicable given the field names carried over unchanged, but not re-confirmed).

Limit & Deductible step
Matches the old popup's "Limits/Deductibles Of Insurance" grid closely: a "Limits" panel with Default Limit dropdown, Building Limits($)/Co-Ins(%)/Valuation/Cause of Loss/Rate(%)/Credit-Debit/Final Rate/Premium($) row, an identical Personal Property Limits($) row, an "Expense" row (checkbox) for BI/Rents Limits($) with its own "ML" checkbox, an "Other Coverage($)" row, an "Other Structure($)" row, an "Equipment Breakdown" checkbox row (with its own Rate(%) and Premium), then TIV($), Minimum Premium($), Total Premium($), a "Round Amount" checkbox (checked by default), and Rated/Non-Rated toggle buttons; below that, Wind/Flood/Theft/Earthquake/AOP Limits($) rows (Theft additionally shows a "Theft Premium" box; Earthquake has an "Included" checkbox) and an "Add Optional Coverage" expandable link — this is the direct successor to the old popup's separate "Optional Coverage/Limits/Deductibles" tab, now folded into this same step instead of being a whole separate tab. A collapsed "Deductible Details" section sits below (not expanded/exercised in this pass, but is presumed to hold the same Wind Zone/Flood Zone/Wind/Earthquake/Flood/AOP/Other/Named Storm/Named Hurricane/Water/Theft/Wind-Hail deductible fields the old popup had directly on this tab).

Protective Devices step
Its own dedicated step now (previously a section within the old popup's single long Property Information tab): #Fire Division, Territory Code, #Units in Fire Division, Fire District Code Number, Distance To Hydrant (feet), Fire/EC Rate(%), Distance To Fire Station (miles), Premium Group, Sprink(%), a "Does This Home Have A Sprinklers?" Yes/No/None radio (defaults None), and three side-by-side device-type checkbox groups — Centralized Protection Device Type, Direct Protection Device Type, Local Protection Device Type — each offering Smoke/Temp/Burglar checkboxes (the old popup's single "Protection Device Type" grid with System/Smoke/Temp/Burglar columns for Central/Direct/Local is the same data, just relaid-out as three explicit groups instead of a grid).

Scheduled Items step
New in this UI — no equivalent existed in the old popup. A "Schedule Property Details" form: Schedule Type dropdown (required — its option list wasn't retrieved in this pass, the dropdown didn't visibly open on the attempted click), Amount($), Rate(%), Premium($) with a calculator icon and a "Round Amount" checkbox (checked by default), and Cancel/Save Changes buttons. Presumably used for scheduled/itemized property (e.g. named high-value items) distinct from the blanket Building/Personal Property limits on the Limit & Deductible step. Not exercised beyond opening it — no schedule was actually added or saved.

Additional Questions step
The same Service Station Program + Named Storm field set documented in `add-edit-risk.md` under General Liability's own Additional Questions step (Discretional Adjustment Type*, Underlying Policy Number*, GC TIER*, Tier Factor Number*, Crime Score*, Operations Type*, then Risk Company of underlying Property or Package that excludes Named Storm coverage*, Underlying Property or Package that excludes Named Storm coverage*, Building – Percent Completed (Builders' Risk Only)*, Building Code Effectiveness Grading (BCEG) Classification Code*, Named Storm Deductible*, Named Storm Ded Min Per Occurrence*) — every field marked required in this layout. This is the last step (only a "Previous" button, no "Next"/"Save"). Whether this is the same underlying data as General Liability's identical-looking step, or an independent copy scoped to this building, is not confirmed from the UI alone.
